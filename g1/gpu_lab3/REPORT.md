## 1. Определитель методом Гаусса

Для вычисления определителя выполняется прямой ход метода Гаусса с частичным выбором главного элемента. На шаге `k` находится строка с максимальным модулем в столбце `k` среди строк `k..n-1`. Если нужно, строка меняется местами с текущей; каждая перестановка меняет знак определителя. Затем из строк ниже вычитаются кратные ведущей строке, формируя верхнетреугольную матрицу. Определитель равен произведению диагональных элементов с учётом знака перестановок. Если ведущий элемент близок к нулю, матрица считается вырожденной.

CPU-реализация находится в `src/tasks.cpp`, GPU kernels — в `kernels/determinant.cl`. На GPU `pivot_swap` выполняет поиск/перестановку в одном work-item, а `eliminate_submatrix` параллельно обновляет элементы подматрицы. Между зависимыми шагами `k` запускаются отдельные kernels.

Сложность: O(n³) операций и O(n²) памяти для обеих реализаций; GPU параллелит обновления на каждом шаге, но шаги исключения остаются зависимыми друг от друга. Логическое число work-items для обновления на шаге `k` равно `(n-k-1)²`; global size округляется вверх до кратного `L`, где `L = min(64, CL_DEVICE_MAX_WORK_GROUP_SIZE, CL_KERNEL_WORK_GROUP_SIZE)`. Число work-groups вычисляется как `ceil((n-k-1)² / L)`. Для kernel выбора pivot global/local size равны 1. Лишние work-items после округления сразу завершаются по проверке границы.

## 2. Брутфорс MD5

CPU и GPU перебирают строки выбранного алфавита. Для строки длины `L` и алфавита размера `A` существует `A^L` кандидатов. Каждый кандидат проходит padding MD5 для одного 512-битного блока, 64 раунда сдвигов и нелинейных функций, затем вычисленный хэш сравнивается с целевым.

На GPU глобальный индекс work-item преобразуется в кандидата в системе счисления с основанием `A`. Перебор разбивается на порции максимум 262 144 work-items. Найденный индекс передаётся через три целых значения: флаг и две 32-битные части индекса; atomic compare-and-swap назначает единственного победителя.

Сложность полного перебора: O(A^L · L), практически O(A^L) при коротких строках. На CPU кандидаты проверяются последовательно; на GPU независимые кандидаты вычисляются параллельно. Логическое количество кандидатов в порции — до 262 144; global size округляется вверх до кратного `L`, где `L = min(64, CL_DEVICE_MAX_WORK_GROUP_SIZE, CL_KERNEL_WORK_GROUP_SIZE)`. Число work-groups — `ceil(batch / L)`, а добавленные при округлении work-items завершаются по проверке индекса.
