# Лабораторная работа №3 — вычисления на GPU с OpenCL

В проекте реализованы обе задачи из методички:

1. **Определитель квадратной матрицы методом Гаусса** с выбором главного элемента по столбцу. Есть CPU-эталон и OpenCL-реализация: выбор/перестановка строк выполняется отдельным kernel, а обновление оставшейся подматрицы параллелится по элементам.
2. **MD5 brute force**: CPU и OpenCL-версии перебирают кандидаты заданного алфавита и диапазона длин. Найденный пароль дополнительно проверяется на CPU.

В комплекте: самопроверки, команда `benchmark` для замеров, CSV и скрипт для графиков. Замеры нужно выполнить на своём ноутбуке: время не зашито в отчёт, потому что оно зависит от драйвера, режима питания и установленного OpenCL runtime.

## 1. Что нужно установить

Для Windows 10/11 и VS Code:

- CMake 3.20 или новее;
- компилятор C++17: MSVC Build Tools или MinGW-w64;
- расширение VS Code **C/C++**;
- для GPU — драйвер производителя видеокарты и OpenCL SDK (заголовки + ICD loader/import library).

**Важно для ASUS Vivobook M3604YA.** Эта серия выпускается с разными конфигурациями Ryzen 5/7 и встроенной AMD Radeon Graphics. Проверьте точный CPU в «Диспетчер задач → Производительность» и наличие GPU через `lab3 devices`. Само наличие Radeon Graphics не гарантирует, что OpenCL runtime уже установлен. Если команда сборки сообщает, что OpenCL не найден, проект всё равно соберёт CPU-версию, но для зачёта GPU-части нужно поставить OpenCL SDK и пересобрать.

## 2. Сборка в VS Code на Windows

Откройте в VS Code **папку `gpu_lab3`**, а не отдельный файл.

### Вариант A — уже настроен компилятор и OpenCL SDK

Откройте **Terminal → New Terminal** и выполните:

```powershell
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
```

Запускаемый файл обычно будет в `build\Release\lab3.exe` при MSVC или в `build\lab3.exe` при MinGW. Примеры ниже используют `build\Release\lab3.exe`; замените путь на свой, если CMake сгенерировал другую структуру.

Можно также запустить VS Code Task: **Terminal → Run Task → CMake: Build**. Скрипт `scripts\build_windows.ps1` делает configure + build. Для запуска тестов/демо используйте `scripts\run_tests_windows.ps1` и `scripts\run_demo_windows.ps1`.

### Вариант B — OpenCL не находится

Установите OpenCL SDK (заголовки Khronos и ICD loader) и убедитесь, что драйвер AMD установлен с сайта производителя. Затем повторите CMake configure/build. Компилятор должен видеть `CL/cl.h`, а CMake — пакет OpenCL. OpenCL ICD loader сам по себе не заменяет драйвер реализации GPU.

Если SDK пока не установлен, команда сборки создаст CPU-вариант — он полезен для проверки алгоритмов, но `--device gpu` работать не будет.

## 3. Быстрый запуск

В PowerShell из корневой папки проекта:

```powershell
.\build\Release\lab3.exe devices
.\build\Release\lab3.exe test
.\build\Release\lab3.exe demo
```

`demo` запускает определитель для матрицы 64×64, затем ищет MD5-хэш строки `042` в наборе из цифр. В режиме `auto` программа предпочитает OpenCL GPU, а при отсутствии устройства сообщает причину и использует CPU там, где это возможно.

## 4. Команды

```text
lab3 devices
lab3 det --size 128 --seed 42 --device auto
lab3 det --size 256 --device cpu
lab3 md5 --target 202cb962ac59075b964b07152d234b70 --charset digits --min-length 1 --max-length 3 --device auto
lab3 md5 --target <32-hex> --charset lower --min-length 1 --max-length 5 --max-candidates 5000000
lab3 benchmark --csv benchmark.csv
lab3 benchmark --quick --csv benchmark.csv
lab3 test --device cpu
```

Алфавиты: `digits` = `0123456789`, `lower` = `abcdefghijklmnopqrstuvwxyz`, `alnum` = цифры + строчные латинские буквы. Значение `--max-candidates` по умолчанию равно 5 000 000, чтобы случайно не запускать непрактично долгий перебор. Если лимит исчерпан, программа сообщит об этом.

Для своей цели MD5 передавайте **ровно 32 шестнадцатеричных символа**. Брутфорс проверяет только указанный алфавит и длины: если исходная строка не входит в это пространство поиска, совпадение не будет найдено.

## 5. Бенчмарки и графики для отчёта

Полный набор тестов использует размеры матриц 32, 64, 128, 256 и перебор 1 000 000 MD5-кандидатов. Для быстрой проверки используйте `--quick` (матрицы 16, 32, 64 и 1 000 кандидатов).

```powershell
.\build\Release\lab3.exe benchmark --csv benchmark.csv
python -m pip install -r requirements.txt
python scripts\plot_benchmarks.py benchmark.csv
```

Создаются `matrix_benchmark.png` и `md5_benchmark.png`. Чтобы автоматически перенести цифры из CSV и графики в Word-отчёт, выполните `python scripts/fill_report.py benchmark.csv Отчет_ЛР3.docx Отчет_ЛР3_заполненный.docx`. Время определителя включает выделение/копирование памяти и вычисление, но не компиляцию OpenCL kernel. Для повторяемых результатов используйте один и тот же режим питания, закройте ресурсоёмкие приложения и сохраните вывод `lab3 devices` вместе с CSV.

## 6. Описание параллелизма

### Определитель

На шаге `k` алгоритм выбирает строку с максимальным по модулю элементом в текущем столбце, при необходимости меняет строки местами, затем исключает переменные ниже диагонали. На CPU операции обновления подматрицы выполняются вложенными циклами. На GPU kernel `pivot_swap` запущен с одним work-item, так как поиск pivot и перестановка — последовательная часть шага. Kernel `eliminate_submatrix` запускает по одному work-item на каждый элемент подматрицы размера `(n-k-1) × (n-k-1)`; каждый work-item обновляет одну ячейку. Между шагами `k` kernels ставятся в одну in-order очередь OpenCL.

- CPU time complexity: **O(n³)**; память **O(n²)**.
- GPU: арифметическая работа **O(n³)**, но обновление каждой подматрицы распараллелено; из-за зависимости по шагу `k` и запуска kernel остаётся `O(n)` последовательных фаз. Память **O(n²)**.
- `logical work-items` для обновления на шаге `k`: `(n-k-1)²`; global size округляется вверх до кратного `L`, где `L = min(64, CL_DEVICE_MAX_WORK_GROUP_SIZE, CL_KERNEL_WORK_GROUP_SIZE)`. Число work-groups: `ceil((n-k-1)² / L)`. Для `pivot_swap` global/local size равны 1. Work-items в добавленном при округлении хвосте сразу завершаются по проверке границы.

### MD5 brute force

Каждый work-item получает глобальный индекс кандидата, переводит его в строку заданной длины в системе счисления с основанием `alphabet_size`, вычисляет MD5 для одного 512-битного блока и сравнивает четыре 32-битных слова с целевым хэшем. В GPU-версии кандидаты запускаются порциями до 262 144 work-items, чтобы не отправлять весь диапазон одним заданием. Найденный индекс хранится как две 32-битные части; атомарный compare-and-swap гарантирует, что только один work-item записывает результат.

- Для алфавита размера `A` и длины `L`: количество кандидатов `A^L`.
- Время полного перебора: **O(A^L · L)** (в данной версии длина ограничена 12; стоимость собственно MD5 для короткой строки постоянна, поэтому practically это **O(A^L)**).
- CPU выполняет кандидаты последовательно; GPU распределяет кандидаты между work-items. Максимум в одной порции — **262 144 логических кандидата**; global size округляется вверх до кратного L, где L = min(64, максимальный допустимый размер work-group устройства и kernel). Число work-groups вычисляется как ceil(batch/L); лишние work-items завершаются по проверке индекса.

## 7. Тесты корректности

`lab3 test` проверяет известные MD5-векторы, определители обычной и вырожденной матриц, перестановку строк при нулевом диагональном элементе, а также GPU-реализации, если OpenCL GPU доступен. Команды `det` и `benchmark` сравнивают GPU-определитель с CPU-эталоном.
